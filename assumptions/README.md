# 前提の一覧

本プロジェクトの前提（仮定）とその候補を、1 件 1 ファイル（`A-NNNN.md`）で管理します。書式は [`_template.md`](_template.md) のとおりです。

- 前提は、定義でも予想でもなく、議論の土台とする主張です。採用したものだけでなく、作業上のものと未定の候補も、状態を付けて載せます。前提を変えて得られる体系を比べることも、本プロジェクトの方針です（第 08 回）。
- 前提を定理として導けるかを問うものは、予想として別に登録します（例：[C-0004](../conjectures/C-0004.md)）。
- 前提の種類（物理的・方法論的・数学的な技術上の前提など）の欄は設けません。立場によって判断が分かれうるためです（第 10 回のユーザーの判断）。

## 状態

| 状態 | 意味 |
| --- | --- |
| 採用 | ユーザーと合意し、以後の議論の土台にするもの（択一の組の前提では、その前提を置く体系の土台にするもの） |
| 作業上 | 暫定的に使うが、未解決の指定が残るもの |
| 未定 | 必要なことは分かっているが、中身が決まっていないもの |
| 廃止 | 使わなくなったもの（ファイルは残し、理由を履歴に書く） |

## 層

[`framework.md`](../framework.md) の構成の層（実験 → 観測量 → 観測量の時空 → 可能な実験 → 可能な観測量 → 点なし時空）のどれに属するかを書きます。

## 依存関係

各ファイルの「依存する ID」から、[`framework.md`](../framework.md) の依存関係の図を `python3 tools/deps_graph.py` で生成します。「## 定義」「## 主張」の本文で ID にリンクするときは、その ID を「依存する ID」か「参照する ID」（依存ではない逆参照・対比・例など）のどちらかに書きます。ある ID がどこから依存・参照・言及されているかは、`python3 tools/id_index.py refs <ID>` で逆引きできます。「関係する予想・結果」には、この項目に依存する予想・結果の ID を書きます（予想・結果のファイルの「依存する ID」と一致することを、`tools/tests/test_framework.py` で検査します）。

## 択一の組と体系

前提を変えて得られる体系を比べるため（第 08 回の方針）、同時には議論の土台に置かない代替の前提の組を「択一の組」として登録します（第 21 回に、ユーザーの判断で導入）。

- 組の前提は、数学的な内容だけなら論理的に排反とは限りません。択一は、同時に土台に置かないという運用上の約束です（例：A-0014 の取り替えと A-0015 の群の取り替えは、両者を結ぶ条件がなければ両立するが、A-0014 は取り替えについてほかの仮定を置かないことを主張に含むので、A-0015 と同時には置かない。PR #43 のレビュー）。
- 組は二つ以上の前提からなり（三つ以上の前提からなる多肢の組も許す。第 21 回に「二者択一の組」から改めた）、各前提は一つの**体系**を定めます。体系の記号は英大文字 1 文字とし（E、P など）、組をまたいで重複させません。組の前提の状態が「採用」であることは、その前提を置く体系の土台にすると合意したことを意味し、組の二つ以上の前提を同時に土台にすることは意味しません。
- 組の前提のファイルには「体系」の行を置きます。組の前提に（間接的にも）依存する定義・前提・予想・結果にも「体系」の行を置き、その体系を書きます（複数の組に依存する場合は、組ごとの体系を「・」で区切って並べます）。一つの項目が同じ組の二つ以上の前提に依存しないこと、「体系」の行が依存と一致することを、`tools/tests/test_framework.py` で検査します。
- 予想が、ある体系で組のほかの前提を導こうとする場合は、その前提を「目標の ID」に書きます（例：[C-0011](../conjectures/C-0011.md) は体系 E で A-0015 を目標とする）。

| 組 | 体系 | 前提 | 体系の内容 |
| --- | --- | --- | --- |
| 1 | E | [A-0014](A-0014.md) | 観測者の取り替えを、比較の実験の記録から経路に付いた部分写像として与える |
| 1 | P | [A-0015](A-0015.md) | 観測者の取り替えを、経路に依らない群の元として前提で与える |
