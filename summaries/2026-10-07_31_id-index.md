**決めたこと（ユーザーの判断。すべて Claude の推奨の案）**
- 意味上の依存と参照の分け方：
  - 意味上の依存は、表の「依存する ID」に限る。予想の「目標の ID」は、仮定せずに導こうとする前提として、依存とは区別する（どちらも、本文のリンクの書き先としては認める）。
  - 「## 定義」「## 主張」の本文の ID のリンクは、どれも「依存する ID」（予想では「目標の ID」も可）か、新しい「参照する ID」の行（逆参照・対比・例など）のどちらかに書く。これを検査する。
  - 循環の検査に使うのは依存だけとする。
- リンクのない ID の言及も、種類「言及」として索引に含める（循環の検査には使わない）。
- 索引のファイルはコミットしない。`tools/id_index.py` が毎回ファイルから作る。
- 索引の形式は RDF のトリプルにする（ユーザーの提案。本プロジェクトの知識のナレッジグラフ化への関心から）。
  - IRI の基底は、公開リポジトリの `main` のファイルの URL とする（`tools/id_index.py` の `BASE` と `tools/pfs.ttl` の接頭辞の 2 か所にあり、変えるときは両方を改める）。
  - 一般的な語彙（`rdf:type`・`rdfs:label`）を使える所では使い、独自の述語は `pfs:` に置く。
  - この回の範囲は、ファイルにある構造と言及までとする。数学・物理の中身どうしの関係の語彙は、新しいタスク T-0026 に回す。
  - テストでは `rdflib` を開発用の依存に加える。
