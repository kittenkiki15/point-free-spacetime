# 2026-09-25 第 01 回: リポジトリの運用ルール

- 対話ログ: [logs/2026-09-25_01_repo-rules.md](../logs/2026-09-25_01_repo-rules.md)

## 要約

プロジェクトの最初のセッションとして、公開リポジトリ `point-free-spacetime` と非公開リポジトリ `point-free-spacetime-private` の運用ルールを、対話を通して決めた。
あわせて、Lean 4 + Mathlib による形式証明と、Python による数値実験を、このクラウド環境と GitHub Actions の両方で実行できることを確認した。

## 決定事項

### リポジトリの構成

- 公開リポジトリ（CC0 1.0）に、対話ログ（`logs/`）、まとめ（`summaries/`）、調査メモ（`surveys/`）、用語一覧（`glossary.md`）、参考文献一覧（`references.bib`）、予想（`conjectures/`）、Lean のコード（`lean/`）、Python のコード（`sim/`）を置く。
- 非公開リポジトリに、論文の PDF（`papers/<引用キー>.pdf`）と公開に向かないメモ（`notes/`）を置く。引用キーは公開側の `references.bib` と揃える。

### 検証

- 対話で出てきた定理・命題は、可能なものを Lean 4 + Mathlib で形式的に検証し、そのコードを公開する。
- 物理モデルのシミュレーションなどによる検証は Python で行い、そのコードを公開する。
- Lean が保証するのは形式化した命題の正しさだけなので、形式化が元の主張を正しく表しているかは別に確認する。

### 予想の管理

- 未検証の主張は「予想」として 1 件 1 ファイルで管理する。
- 確度・重要度・検証費用を「高・中・低」の段階で評価する。優先度は対話の中で決める。
- 予想の内容と評価はファイルで、作業の進み具合と議論は GitHub の Issue で管理する。

### 対話ログ

- セッション記録を変換した生ログ（個人情報などは除去）と、整形したまとめの両方を置く。

### 著作権・公開範囲

- 公開側には他者の文章の長い引用、図、PDF を置かない。書誌情報と短い引用にとどめる。

### 言語と表記

- 文書は日本語を基本とし、用語一覧では英語の原語を併記する。
- 数式は、ユーザーが Firefox と Chrome で表示を確かめてまとめた [`docs/math-guide.md`](../docs/math-guide.md) に従う。

### Git の運用

- 作業ブランチから `main` への PR にする。
- PR のたびに、OpenAI の `gpt-6-sol` による AI コードレビュー（クロスモデルレビュー）を GitHub Actions で自動実行する。
- コミットメッセージは日本語で書く。
- セッションの終わりに、毎回ログとまとめをコミットする。
- セッションの後はコンテキストを `/clear` で初期化するので、次にやることを [`NEXT.md`](../NEXT.md) に残す。

## 得られた結果（検証済み）

- このクラウド環境で Lean 4（v4.34.1）と Mathlib を使えることを確認した。
  - ネットワーク設定で `releases.lean-lang.org`・`cache.mathlib.org` などを許可した。
  - `reservoir.lean-lang.org` にはアクセスできないため、Mathlib は `lakefile.toml` で GitHub の URL を直接指定する。
  - Mathlib のビルド済みキャッシュの取得には約 2 分かかる。
- Mathlib を使って、フレームにおける分配律 $`a ⊓ (b ⊔ c) = (a ⊓ b) ⊔ (a ⊓ c)`$ を検証した（[`lean/PointFreeSpacetime/Basic.lean`](../lean/PointFreeSpacetime/Basic.lean)）。Mathlib にロケール（`Locale`）が定義されていることも確認した。
- `lake build --wfail` により、`sorry` を含む証明がビルド失敗になることを確認した。
