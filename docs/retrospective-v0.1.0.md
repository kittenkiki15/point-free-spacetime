# v0.1.0 以降の振り返り

作成: 2026-10-12（第 42 回。たたき台）

対象は、リリース `v0.1.0`（第 32 回）の後の第 33〜41 回と、v0.1.0 に向けて行った運用の改善（第 29〜32 回の T-0025・T-0027）の効果です。前回の振り返りは [`retrospective-stage-A.md`](retrospective-stage-A.md)（第 28 回）にあります。評価は、断りのない限り Claude のたたき台で、ユーザーのコメントを受けて改めます。

## 0. 数字の出し方

- 対話ログ（`logs/`）を `python3` の短いスクリプトで数えた。第 29 回以降のログは 1 ターンごとの自動変換（タイムスタンプ付き。PR のマージまでの発言を含む）、第 28 回までのログはセッションの終わりの書き出し（PR の作成まで。ツールの要約の行を含む）で、**形が違うので、両者の比較は目安にとどまる**。
- 「英語だけの発言」は、ひらがな・カタカナ・漢字を 1 字も含まず、英字の語を含む Claude の発言を数えた。
- PR の数字は、`main` の履歴（マージした PR のコミット）と、PR のコメント（クロスモデルレビューのボットのコメント）から数えた。レビューの指摘の件数は、各節の箇条の数である。

### 1.3 評価（Claude）

### 2.2 効果があった点

- **文脈の分岐からの復旧が、毎回できた。** 1 ターンごとの対話ログと作業ブランチのコミットで、前の文脈の下書きと質問を確かめてから続けた（第 38 回は、ログに最後の提案が残っておらず、セッション記録で確かめた）。第 29 回より前は、分岐に気づかずに進む恐れがあった。
- **内容の主な変更の多くが、ユーザーの指摘から生じた。** A-0001 の改定と A-0018（第 37 回）、A-0016 の目的（第 38 回）、C-0004 の真性乱数（第 39 回）、オプショナルな前提（第 40 回）、Q-0011 の目的（第 41 回）。Claude の下書きに対して、ユーザーが物理的な意図を補う分担が働いている。
- **判断の根拠を追える。** 各決定に「ユーザーの判断」「ユーザーの提案」などを付け、ログで発言まで遡れる。

### 2.3 改善点

- **英語の途中経過が混じる。** 英語だけの Claude の発言は、第 29〜32 回に 13%（387 件中 52 件）、第 33〜41 回に **24%（348 件中 82 件）** と増えた。`CLAUDE.md` の「チャットでの Claude の回答（途中経過の報告を含む）は、必ず日本語で書く」に反している（この回の最初の応答にも 1 件あった）。ほとんどは、ツールの呼び出しの前の短い一文である。
- **ユーザーの入力が減り、Claude の出力の比が大きい。** 1 回あたりのユーザーの字数は、第 28 回までの 2,500〜3,600 字から、約 1,100 字に減った。T-0028 が「Claude が下書きし、ユーザーが確かめる」形の作業だったことが大きいが、ユーザーが読む量（1 回あたり約 16,000 字）の負担もある。報告は、判断の要る点を先に、短く書くべきである。
- **文脈の分岐は、ほぼ毎回起きる。** 原因は環境の側にあり、こちらでは防げない。復旧の手順は定着したが、毎回、確かめる手間がかかり、最後の同期の後の発言が失われることがある。

### 3.3 今後改善が必要な運用上の課題（候補）

1. **英語の途中経過**（2.3）。対策案：`live_log.py sync` の報告に、日本語を含まない Claude の発言の件数を出す（保留はしない）。あるいは、`CLAUDE.md` の規則の位置を、ツールの呼び出しの前の一文にも当たると明記する。
2. **レビューの小出しの往復**。対策案：PR を作る前に、Claude が差分の要約・`NEXT.md`・各回の状況の段落を、本文の条件と突き合わせる自己点検を行う（指摘の多い型：要約での条件の落ち、断定の強さ、数式の表記）。
3. **報告の長さ**（2.3）。対策案：応答の冒頭に「判断をお願いしたい点」を置き、下書きの全文はコミットのリンクで示す。
4. **索引（T-0025 の 4）の使い道**。使用が少ないので、使う場面（たとえば T-0028 の層 2 以降で、依存の先から書く順序を決める）を決めるか、今のまま保守だけにする。
5. **文脈の分岐**。環境の側の要因なので、復旧の手順（ログとコミットで確かめる）を続ける。最後の同期の後に長い文を書かない運用を守る。
