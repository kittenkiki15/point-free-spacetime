# 成果物の見直しの手順

ロードマップの各段階を終えるときに行う、成果物の見直しの手順です。第 27 回（T-0021。段階 A のクロージング）のやり方を、ユーザーの依頼で手順にしました。

## いつ行うか

- ロードマップの各段階（段階 B・C・D など）の最後のタスクを終えたら、次の段階に入る前に、成果物の見直しのタスクを 1 件置く（[`roadmap.md`](../roadmap.md) の「使い方」）。
- タスクの「関係する ID」は「横断的なタスク（特定の ID はない）」とする。
- 見直しの後に振り返り（T-0022 と同じ型）を置くかどうかは、その都度ユーザーと相談する。

## 進め方

1 セッションで行い、各項目の節目でユーザーに結果を見てもらう。Claude は 1 件ずつ見立て（根拠つき）を示し、ユーザーが判断する。

順序は次のとおり（第 27 回にユーザーと決めた順序）。

1. **予想と Issue の照合**：予想ファイルの Issue 番号・状態・優先度と、GitHub の Issue の開閉・`priority:*` ラベル・タイトルが一致しているかを確かめる（機械的に確かめられる）。
2. **予想の棚卸し**：全予想の確度・重要度・検証費用を、登録後の調査や詳細化の論点を反映して見直す。優先度はユーザーが決める。決まったら、予想ファイル（「評価の根拠」に変えた理由ともとの評価を書く）、一覧表（優先度の順に並べ直す）、Issue のラベルをまとめて更新する。
3. **定義・前提の状態の更新**：「作業上」の項目のうち、本文が固まり、残った未解決の点が使い方や拡張に関するものに限られる項目を、「採用」の候補として示す。依存先に「作業上」の項目がある場合は、依存先が改まったときに見直すと注意に書き添える。採用はユーザーと合意したときに限る。
4. **文章の校正**：
   - 機械的な検査：数式の書き方（[`math-guide.md`](math-guide.md)）、判断前の書き方の残り（「次に判断する」など）。
   - 手で読む校正：未解決の点・詳細化の論点が長くなったファイルを整理する。本文に入った内容は外し、経緯は要点と調査メモへのリンクに縮め、問いそのものは変えない。ファイルごとに結果を見てもらってから確定する。
5. **割り当てのない論点の洗い出し**：未解決の点・詳細化の論点を持つファイルが、どれかの未完了のタスクの「関係する ID」にあるかを確かめる（ファイルの掲載漏れは `tools/tests/test_framework.py` で検査する。一つのファイルの論点を複数のタスクに分けるときは、各タスクの節に扱う論点が書かれているかを手で確かめる）。割り当て先や新しいタスクはユーザーと決める。
6. **一覧の抜けの確認**：本文で使っているのに一覧にないものを抽出する。
   - 参考文献：本文の引用キーが `references.bib` にあるか。著者名と年だけで言及している文献のうち、未確認のものは [T-0014](../tasks/T-0014.md) に記録する（原典を確かめてから登録する）。
   - 記号：その段階で導入した記号が `symbols.md` にあるか。
   - 用語：定義・前提の太字の語のうち、用語として載せる価値があるものが `glossary.md` にあるか。

## 記録

- 見直しの結果は、そのセッションのまとめに書く。
- 決めた内容は、各ファイルの履歴（「第 NN 回の棚卸し」など）と、見直しのタスクのファイル（`tasks/T-NNNN.md`）に残す。
