## 目的

装置の構成的な定義（[T-0034](../tasks/T-0034.md)）の土台として、プロトコルの記述を書く言語と、どの記述も停止することを保証する仕組みを決める（第 54 回に、[Q-0013](Q-0013.md) の完了の条件の (4) と、関係する論点を移して新設した。ユーザーの提案）。決めたら、[A-0018](../assumptions/A-0018.md) の 1 の「有効なプロトコル」を、この言語の有効な記述として読み直し、[A-0002](../assumptions/A-0002.md) の有限の記述を、この言語のプログラムとして述べる。[C-0019](../conjectures/C-0019.md)（有効な記述の実行可能性）と [C-0020](../conjectures/C-0020.md)（等価原理の分解）は、ここで決めた言語の上で述べる。

## 完了の条件

次を決めたら、解決にできる。(1) 言語の構文の要素：部品の呼び出し、部品の出力の有限の記号による分岐、逐次の実行、繰り返し、制御部の記憶（変数）。(2) 停止の保証：打ち切りの上限を構文に含める形（上限の値を記述の定数にするか、設定の座標の関数を許すか、上限に達したときに記録する ⊥ の扱い）。(3) 計算機の部品の能力のクラス（[Q-0013](Q-0013.md) の結論の 2）と言語の関係：言語をクラスごとに定めるか、一つの言語の部分言語でクラスを表すか。(4) 有効性（構文に合うこと）が判定できることと、A-0018 の 1 の「有効な」の読み替え。(5) 結果を返さない分岐の扱い：[A-0004](../assumptions/A-0004.md) の 3 の消費量の有界性を、結果を返さない分岐にも及ぶと読むか。

## 論点

- 第 54 回の整理（Claude の見立て。ユーザーが同意）：(2)・(4) の目的は、[A-0018](../assumptions/A-0018.md) の列挙の制限（1）と資源の制限（2）の間に残る穴（有限の記述だが実行できない手順。停止問題の答えで分岐する手順など）をふさぐこと（P3）と、装置の構成的な定義の (a)「有限の手続き」の意味を部品の実行として与えること（P4）である。記述を「計算機の部品が実行する、部品を呼び出す言語のプログラム」と定めれば、有効な記述はどれも定義から実行できる（[C-0019](../conjectures/C-0019.md)）。ただし、計算機の部品を制限のない Turing machine とすると、構文に合うこと（構文上の有効性）は判定できるが、構文に合う任意のプログラムが停止することは保証できない（停止は構文からは判定できない意味論的な性質である）。そこで、停止を保証する構文上の制限として、時計の部品による打ち切りを構文に組み込む案にした（PR #93 のレビューで、構文上の有効性と停止の判定を分けた）。
- 停止と連続性（第 54 回。Claude の見立て。PR #93 のレビューで限定した）：停止しない分岐を許す一般の手続きでは、出力は合計が 1 未満になりうる分布（劣確率測度）になり、計算について下からの情報しか保証できない場合がある（下半計算可能）。ただし、停止しない分岐があっても、応答が計算可能で連続な場合はある（例：設定によらない公平なコインを表が出るまで投げ、表が出たら結果 0 を返す手続きは、裏が続く分岐では停止しないが、ほとんど確実に停止し、応答は一定の $`δ_0`$ である）。したがって、すべての分岐が上限以内の段数で停止することは、連続性の必要条件ではなく、[C-0020](../conjectures/C-0020.md) の構成で採用する十分条件であり、資源の上の制約（[A-0004](../assumptions/A-0004.md) の 3）でもある。
- [Q-0013](Q-0013.md) から移した論点（もとは A-0002）：プロトコルを計算可能な手続きとして形式化するかどうか。第 54 回の方針では、この言語のプログラムとして形式化する。
- [Q-0013](Q-0013.md) から移した論点（もとは A-0018）：手順の実効性：A-0018 の 1 は記述の列挙を制限するだけで、記述された手順が計算・実行できることは保証しない。手順の実効性を要件にするかを、A-0018 の 2 の実行の計算資源と合わせて決める（PR #51 のレビュー）。第 54 回の方針では、要件にし、計算機の部品がプログラムを実行することで満たす。
- [Q-0013](Q-0013.md) の第 53 回の詳細化の論点から移した論点：資源の一様な上界から「停止する計算」を導くとき、結果を返さない分岐（無限の繰り返しに入る分岐）にも上界が及ぶかを確かめる。A-0004 の 3 はすべての結果 $`y ∈ Y_π`$ の消費量の記録を抑えるが、結果を返さない分岐は記録を持たないので、すべての分岐の停止を別に要求するか、A-0004 の有界性に含まれると読むかを決める。第 54 回の案では、打ち切りを記述に含めて、結果を返さない分岐をなくす（打ち切りの上限に達した分岐は ⊥ を記録する）。
- A-0018 から移した論点：プロトコルの記述の言語：$`M`$ が出力する記述の形式と、「有効な」の定め方。
- [Q-0014](Q-0014.md) との分担（第 54 回）：制御の流れ（逐次・分岐・繰り返し、適応的な設定の選び方）はこの Q で、物理的な合成（並列の合成とテンソル積、結合の型づけ、局所性、インストルメントなど）は Q-0014 で決める。

- 部品の呼び出しの終了（PR #93 のレビューの詳細化の論点）：繰り返しの上限だけでは、呼び出した部品が戻ってこない場合（「信号を受信するまで待つ」呼び出しなど）を扱えない。各原始操作の終了の約束（必ず結果を返す操作だけを許すか、非同期の呼び出しと独立の打ち切りの仕組みを設けるか）を決め、記述の上の呼び出しの回数の有限性と、物理的な終了・記録の保証を区別する（[Q-0020](Q-0020.md) と合わせて決める）。
- 設定の関数としての打ち切りの上限（PR #93 のレビューの詳細化の論点）：上限を設定の座標の関数として許すと、設定の座標が有界でも、関数が有界とは限らない（例：$`0 < B ≤ 1`$ に対する $`⌈1/B⌉`$）。上限の関数に許す形（予算の座標から単調に制限するなど）を決めるか、設定全体に共通の上界を別に求める。停止の証明で上界を算出するなら、その上界が記述から実効的に得られることも確かめる。

## 第 55 回の検討（下書き。Claude の案）

### (1) 構文の要素

部品の組 $`𝔅`$（[Q-0013](Q-0013.md) の結論）ごとに、制御部のプログラムを書く言語 $`𝓛_𝔅`$ を定める。要素は次のとおり。

- **値**：制御部が扱う値は、有限の記号（部品の出力の記号の集合の元）と自然数だけとする。設定の実数の座標は、制御部の値にしない。
- **変数**（制御部の記憶）：値を入れる変数。代入 `v := e`。式 `e` は、定数、変数、自然数の加法・乗法、記号の比較から作る。
- **部品の呼び出し**：`v := call b(a₁, …, a_k)`。`b` は $`𝔅`$ の部品で、引数 `aᵢ` は、変数か、設定の座標への参照 `x_j` である。設定の座標は、作動の部品と読みの部品への引数としてだけ渡せる（そのまま通すだけで、制御部は値を調べない）。戻り値は、部品の仕様が定める有限の記号の集合の元である。
- **分岐**：`case v of a₁ → P₁ | … | a_m → P_m`。分岐の対象は、変数の値（有限の記号、または自然数の比較の結果）に限る。
- **逐次の実行**：`P ; Q`。
- **繰り返し**：`repeat e times P`。回数 `e` は、繰り返しに入るときに一度だけ評価し、本体の中で変えても回数は変わらない（LOOP 言語の形。Meyer–Ritchie。記憶によるもので、未確認）。
- **結果の記録**：`emit e`。記録した値の列を、1 回の観測の結果 $`y ∈ Y_π`$ とする。
- **便宜の構文**：`until c within e do P`（`c` が成り立つか、`e` 回に達するまで `P` を繰り返し、達したら記号 ⊥ を記録する）。`repeat` と `case` で書き直せるので、上の要素を増やさない。

設定の座標を制御部の値にしないのは、[C-0020](../conjectures/C-0020.md) の仮定 1・2（設定は作動の部品と読みの部品を通してだけ入り、制御部は有限の記号で分岐する）を、構文で保証するためである。設定の値で分岐したいときは、読みの部品（有限の精度で読み、記号を返す）を呼び出す。[C-0004](../conjectures/C-0004.md) の経路（制御部が設定の名前を有限の接頭部まで読む）は、設定の座標の名前を記号として返す読みの部品として表せる。

### (2) 停止の保証

繰り返しは `repeat` だけにする。`repeat` の回数は入るときに決まり、変数への代入で増やせないので、どのプログラムも、どの実行でも停止する（部品の呼び出しが必ず戻る場合。下の (5)）。部品の出力を外部の入力として扱うと、制御部の計算（代入・分岐の段数と、部品の呼び出しの回数）は、部品の出力に相対的に原始再帰的な上界を持つ（LOOP 言語の既知の性質を、部品への相対化として当てはめたもの。記憶によるもので、未確認）。部品は測定・乱数・物理的な操作で、原始再帰的な数値関数とは限らず、確率的な測定を含むプログラム全体は決定的な数値関数ではないので、この主張は制御部の計算と呼び出しの回数に限る。物理的な呼び出しの時間まで含めた上界には、部品の側の時間の上界の条件を別に置く（下の (5)。PR #97 のレビューで限定した）。

打ち切りの上限は、`repeat` の回数の式として構文に入る。次の 3 種類の形を許す。

- 記述の定数（`repeat 1000 times …`）。
- 前に部品から得た値から計算した自然数（測定の結果に応じて回数を変える適応的な手続き）。
- 予算の座標：予算の座標は、予算を読む部品（自然数を返す）を通して制御部に入る。[A-0005](../assumptions/A-0005.md) によって、予算の座標の値域はプロトコルごとに有界なので、返る自然数もプロトコルごとに有界である。

上の 3 種類のどれでも、プロトコルごとに、すべての設定と部品の出力にわたって一様な段数の上界がある。部品の出力の記号の集合が有限で、予算を読む部品の値域が有界なので、プログラムの構造についての帰納法で、上界を記述から計算できる見込みである（[C-0019](../conjectures/C-0019.md) の主張の一部）。上限を設定の座標の任意の関数にしないので、論点の $`⌈1/B⌉`$ の例は、予算を読む部品の値域の有界性で除かれる。上限に達した分岐は、⊥ を記録して終わる。

### (3) 計算機の部品の能力のクラスと言語

一つの言語 $`𝓛_𝔅`$ の部分言語として、能力のクラスを表す。

- **有限オートマトン**：変数の値を、仕様で決めた有限の集合に限る（自然数の変数を持たない。`repeat` の回数は定数だけ）。
- **時間制限付きの Turing machine**：`repeat` の回数の式を、予算の座標の多項式などのクラスに限る。
- **制限のない Turing machine**：上の (2) の言語の全体。停止を構文で保証するので、プロトコルごとの制御部の計算は、部品の出力に相対的に原始再帰的な段数で終わる（上の (2)。PR #97 のレビューで限定した）。どの計算可能な関数も、予算を十分に大きくしたプロトコルの族として近似される（第 53 回の「制限のない Turing machine の能力は、プロトコルの族の全体として現れる」に当たる）。

計算機の部品の仕様（$`𝔅`$ の元）が能力のクラスを指定し、プロトコルはそのクラスの部分言語で書く。

### (4) 有効性の判定と A-0018 の読み替え

$`𝓛_𝔅`$ の記述が**有効**であるとは、構文に合い、型の検査（部品の呼び出しの引数の個数と種類、戻り値の記号の集合、`case` の網羅、能力のクラスの部分言語に入ること）に通ることとする。どれも記述の有限の検査で、判定できる。停止は (2) で構文から従うので、停止の判定は要らない。A-0018 の 1 の「有効なプロトコル」は、「$`𝓛_𝔅`$ の有効な記述」と読み替える。A-0002 の「有限の記述」は、$`𝓛_𝔅`$ の記述（有限の記号列）とする。有効性が判定できるので、A-0018 の 1 の「$`M`$ は有効なものだけを出力する」は、無効な出力を捨てる機械に置き換えても同じ列挙のクラスになる見込みである（出力の時刻の多項式の上界が保たれるかは、判定の計算量と、無効な出力の密度・遅延による。確かめていない。下の「下書きへのレビューの詳細化の論点」）。

### (5) 結果を返さない分岐

制御の側では、(2) によって結果を返さない分岐がなくなる。残るのは、部品の呼び出しが戻らない場合である。案として、各部品の仕様に「呼び出しは、仕様が定める有限の時間以内に必ず記号を返す」ことを含める（待つ部品は、待つ時間の上限を仕様か引数に持ち、上限に達したら ⊥ を返す）。こうすると、すべての分岐が有限の段数で停止し、A-0004 の 3 の消費量の有界性を、結果を返さない分岐に及ぶと読む必要がない（停止は構文と部品の仕様から従う）。部品の呼び出しの終了の約束の詳細（非同期の呼び出しを許すかなど）は、[Q-0020](Q-0020.md) で決める。

### 下書きへのレビューの詳細化の論点（PR #97）

- 予算を読む部品の出力の型：予算を読む部品も、部品の戻り値を有限の記号の集合にする制約に従うなら、出力は有界になる。「自然数を返す」を、有限の出力の制約の例外にするなら、入力の予算の座標が有界でも出力は有界とは限らない（論点の $`⌈1/B⌉`$ の例）。予算を読む部品の出力を有限の集合にするか、自然数を返す特別な部品にして、出力の上界と、それを記述から実効的に得る方法を仕様に含めるかを決める。
- 繰り返しの回数の制限と、計算の時間の制限の区別：能力のクラスの「時間制限付き」を、`repeat` の回数を予算の多項式に限ることで表すだけでは足りない（例：`v := 2; repeat B times (v := v * v); emit v` は、繰り返しの回数が $`B`$ でも、出力のビットの長さが $`2^B + 1`$ になる）。自然数の演算を単位時間と数えるか、ビットの計算量で数えるかを定め、後者なら、値のビットの長さ・演算の時間・出力の時間も制限する。能力のクラスを具体化するときの条件とする。
- 無効な出力を捨てる機械の列挙の時間：A-0018 の 1 は「時刻 $`P(N)`$ までに出力したプロトコル」で制限するので、無効な出力を捨てると、有効な出力の第 $`n`$ 番目までの時間は、無効な出力の個数と間隔に依存しうる（例：有効な出力が元の列の第 $`2^n`$ 番目にしか現れない場合）。ただし、A-0018 の 1 は $`M`$ が有効なものだけを出力すると課しているので、捨てる機械への置き換えは、上の (4) の補足として述べたものにすぎない。置き換えを使う場合は、無効な出力の密度・遅延も条件に加える。

### ユーザーに判断をお願いする点

1. 設定の実数の座標を制御部の値にしない（作動の部品と読みの部品への引数としてだけ渡す）か。
2. 繰り返しを `repeat`（回数を入るときに決める形）だけにするか。
3. 打ち切りの上限を、記述の定数・部品から得た値・予算を読む部品の値の 3 種類に限るか。
4. 能力のクラスを、一つの言語の部分言語として表すか。
5. 部品の仕様に、呼び出しが有限の時間以内に戻ることを含めるか（詳細は Q-0020）。
