#### 問題：対話ログの push のたびに、レビューが動き直す

- **原因**：`codex-review.yml` には `paths-ignore: ["logs/**"]` があります。ただ、PR のイベントでは、この条件は「その push で変わったファイル」ではなく、「PR 全体の差分」で判定されます。今回の PR には `tools/` などの変更があるので、`logs/` だけを変えた push でも、クロスモデルレビューと `python.yml` が毎回動きます。
- **起きること**：
  1. レビューの結果が届くと、Claude が起きて同期し、ログを push します。
  2. その push で、またレビューが動きます。
  3. 結果が届くと、Claude がまた起きます。

  この繰り返しで、API の料金がかかり続けます。また、`cancel-in-progress` のため、対話が続く間はレビューが途中で打ち切られ続けるおそれがあります。
- **今の扱い**：この繰り返しを避けるため、今回の通知（CI の完了）の後は、ログを同期していません。
- **これまでの影響**：今回のターンまでの push で、レビューと CI は数回、余分に動いたと思われます。

#### 直し方の案

- **案 1（推奨）：ワークフローで「この push の差分が `logs/` だけなら動かない」ようにする**
  - `synchronize` のイベントでは、前と後のコミットの差分を判定できます。`logs/` だけなら、レビューと CI を飛ばします。
  - `codex-review.yml` は安全のため `main` の版で動くので、この直しが効くのは、この PR がマージされた後です。
  - それまでの間は、PR の監視のための自動の起動（ユーザーの発言のないターン）では、ログを push しません。次にユーザーの発言があったターンか、ほかの修正と一緒に push します。
- **案 2：PR を作った後は、ログを push しない**
  - PR を作った後のログは、ローカルにためます。マージの直前に一度だけ push するか、次の回の始めに送ります。
  - ワークフローは変えません。ただし、「PR を作った後からマージまでの発言も残す」という決定を、一部後退させることになります。
