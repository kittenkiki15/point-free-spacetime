# タスク

[`roadmap.md`](../roadmap.md) のタスク（`T-NNNN`）を、1 件 1 ファイルで管理します（第 30 回にユーザーと決めた。T-0025 の 2）。一覧表・進める順序・図は `roadmap.md` にあります。

- 書式は [`_template.md`](_template.md) です。表の項目は、段階・前提のタスク・関係する ID・状態・Issue・追加した回です。本文は「内容」（扱う論点、手がかり、成果物）と「履歴」（どの回に何をしたか）です。
- **状態などの内容はファイルが正本**です。作業の進み具合と議論は、GitHub の Issue（タイトルは `[T-NNNN] <タスクの名前>`）に置きます。予想（[`conjectures/`](../conjectures/README.md)）と同じ分担です。
  - Issue は、未完了のタスクに作ります。第 30 回の時点で完了していたタスクは「Issue なし」とします。
  - タスクを完了にするときは、ファイルの状態と `roadmap.md` の一覧表を同じコミットで改め、Issue を閉じます。Issue の欄は、閉じた Issue へのリンクのまま残します。
- 状態は、未着手・進行中・完了・保留のどれかです。
- 次のことを `tools/tests/test_framework.py` で検査します。
  - `roadmap.md` の一覧表の各行と、ファイルの表（名前、段階、前提のタスク、関係する ID、状態、Issue）が一致すること。
  - 第 30 回の時点で完了していたタスクを除き、Issue の欄が Issue へのリンクの形式であること。Issue の表示の番号とリンク先の番号が一致し、タスクと Q の間で同じ Issue を使わないこと（Issue が実在するかと、その開閉は検査しない）。
  - 未解決の点・詳細化の論点を持つファイルが、どれかの未完了のタスクの「関係する ID」にあること（割り当て漏れ）。数えるのは、ファイルへのリンク（とリンクどうしの「〜」の範囲）で挙げた ID だけです。
- Issue の実在と開閉、ファイルの状態との一致は、今の CI では照合していません（テストは、リポジトリのファイルだけを読みます）。セッションの終わりに、Claude が照合します（[`CLAUDE.md`](../CLAUDE.md) の「セッションの終え方」）。
